# v1.9.1: 微信强行停止后收信与 Android 16 界面修复

## 现场证据

- FCM RECEIVE 广播确实启动微信主进程；Success 并不代表微信已拉取消息和通知。
- 冷启动失败时 Hans 在约 4–10 秒内冻结主进程；未启动 push 服务。
- 后台 AppOp allow 单独设置无效。
- 临时电源豁免对照实验中，12:14:57 首次启动，12:15:08 push 服务启动，12:15:13 发通知；用户确认收到。
- 已存在进程的后续推送约 0.1–6 秒发出通知。一次成功不等于整夜稳定。

## 修复

仅当系统框架确认发送 UID 属于 GMS、action 为 RECEIVE、目标在用户勾选列表且目标 userId 已知时，异步授予 60 秒临时电源豁免。延迟 1 秒申请，避开 AMS 锁和 GMS 自身较短的申请；不是轮询，不添加永久白名单，不直接启动微信页面或私有服务。模块菜单可关闭此功能。重复的同一用户/应用待执行申请合并。

v1.8.1 增加的 fitsSystemWindows 仍存在，但不满足 Android 16 显式边距管理。以 NoActionBar + Toolbar 代替系统 ActionBar，根布局统一消费 systemBars/displayCutout insets，列表在 Toolbar 下方自然排列，避免重复边距。

## 验证要求

构建/JVM 回归测试；实机检查窗口布局和顶部列表；系统框架 Hook 更新需要重启手机后加载。以强行停止→熄屏→新消息验证日志中 Granted 60000ms、push 服务和通知；结束后观察系统恢复冻结。夜间仍需真实消息验证。

## v1.9.2 验证

v1.9.1 临时电源豁免不足，仍被 Hans 提前冻结。v1.9.2 对可信推送目标 UID/包名建立单调时钟 60 秒租约，在已核对的 HansSceneManager.freezeForSceneCombo 返回原生 IMPORTANT；未改变预加载冻结或全局策略。
